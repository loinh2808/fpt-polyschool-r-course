1. SEM nâng cao là gì?

NoteKiến thức nền tảng (Knowledge Notes)

Là gì? (What?)

Mô hình phương trình cấu trúc (Structural Equation Modeling - SEM) là phương pháp phân tích cho phép kiểm tra mối quan hệ giữa các biến tiềm ẩn (Latent Variables) và các biến quan sát (Observed Indicators).

Tại sao cần? (Why?)

SEM hữu ích khi nghiên cứu có:

  • Nhiều construct lý thuyết
  • Nhiều thang đo Likert
  • Nhiều mối quan hệ đồng thời
  • Mô hình trung gian hoặc điều tiết phức tạp
  • Nhu cầu kiểm tra chất lượng thang đo

Khi nào dùng? (When?)

Dùng SEM khi câu hỏi nghiên cứu liên quan đến mô hình lý thuyết, thang đo và quan hệ giữa các construct.

Thực hiện thế nào? (How?)

SEM thường gồm hai phần:

  1. Mô hình đo lường (Measurement Model)
  2. Mô hình cấu trúc (Structural Model)
ImportantỨng dụng trong nghiên cứu (Research Application)

SEM thường được dùng trong:

  • Nghiên cứu giáo dục
  • Nghiên cứu hành vi người học
  • Nghiên cứu chấp nhận công nghệ
  • Nghiên cứu marketing
  • Nghiên cứu quản trị
  • Nghiên cứu tâm lý học
  • Nghiên cứu sử dụng thang đo Likert
WarningSai lầm thường gặp (Common Mistakes)

Người học thường mắc lỗi:

  • Chạy structural model khi chưa kiểm tra measurement model
  • Chỉ báo cáo path coefficients mà bỏ qua model fit
  • Dùng SEM khi không có cơ sở lý thuyết
  • Không kiểm tra reliability và validity
  • Diễn giải SEM cắt ngang như bằng chứng nhân quả mạnh

3. PLS-SEM và CB-SEM

TipKết quả học tập (Learning Outcomes)

  • Phân biệt PLS-SEM và CB-SEM

NoteKiến thức nền tảng (Knowledge Notes)

PLS-SEM là gì?

PLS-SEM (Partial Least Squares SEM) thường được dùng khi mục tiêu là dự đoán, khám phá hoặc khi mô hình phức tạp với yêu cầu phân phối linh hoạt hơn.

CB-SEM là gì?

CB-SEM (Covariance-Based SEM) tập trung vào việc kiểm tra mô hình lý thuyết và độ phù hợp giữa ma trận hiệp phương sai quan sát và mô hình giả định.

Khi nào dùng?

Mục tiêu Gợi ý
Kiểm định lý thuyết mạnh CB-SEM
Dự đoán construct phụ thuộc PLS-SEM
Tập trung model fit CB-SEM
Mô hình khám phá hoặc prediction PLS-SEM
CFA nghiêm ngặt CB-SEM
WarningSai lầm thường gặp (Common Mistakes)

Không nên nói PLS-SEM luôn tốt hơn hoặc CB-SEM luôn tốt hơn.

Lựa chọn phụ thuộc vào:

  • Câu hỏi nghiên cứu
  • Mục tiêu phân tích
  • Lý thuyết
  • Dữ liệu
  • Yêu cầu công bố

4. Mô hình đo lường

TipKết quả học tập (Learning Outcomes)

  • Hiểu biến tiềm ẩn (Latent Variable)

NoteKiến thức nền tảng (Knowledge Notes)

Biến tiềm ẩn là gì? (What is a Latent Variable?)

Biến tiềm ẩn là construct không quan sát trực tiếp được, ví dụ:

  • Performance Expectancy
  • Effort Expectancy
  • Social Influence
  • Trust
  • Behavioral Intention

Biến quan sát là gì? (What is an Observed Indicator?)

Biến quan sát là các câu hỏi hoặc item dùng để đo construct.

Ví dụ:

PE =~ pe1 + pe2 + pe3 + pe4

nghĩa là construct PE được đo bằng 4 item.

Cú pháp mô hình đo lường

measurement_model <- '
  PE =~ pe1 + pe2 + pe3 + pe4
  EE =~ ee1 + ee2 + ee3 + ee4
  SI =~ si1 + si2 + si3 + si4
  FC =~ fc1 + fc2 + fc3 + fc4
  DR =~ dr1 + dr2 + dr3 + dr4
  TR =~ tr1 + tr2 + tr3 + tr4
  BI =~ bi1 + bi2 + bi3
  AU =~ au1 + au2 + au3
'

Trong lavaan:

=~

dùng để khai báo biến tiềm ẩn được đo bởi các item.

CFA là gì? (What is CFA?)

Phân tích nhân tố khẳng định (Confirmatory Factor Analysis - CFA) kiểm tra liệu dữ liệu có phù hợp với cấu trúc thang đo dựa trên lý thuyết hay không.

Tại sao cần? (Why?)

Trước khi kiểm tra mối quan hệ giữa các construct, cần xác nhận rằng các construct được đo lường đáng tin cậy.

Khi nào dùng? (When?)

Giá trị hội tụ là gì? (Convergent Validity)

Các item đo cùng một construct nên hội tụ với nhau.

Chỉ số thường dùng:

AVE > .50

Giá trị phân biệt là gì? (Discriminant Validity)

Các construct khác nhau nên đủ khác biệt với nhau.

Logic Fornell-Larcker:

sqrt(AVE) của một construct nên lớn hơn tương quan của construct đó với construct khác.

Mô hình cấu trúc là gì? (What is a Structural Model?)

Mô hình cấu trúc kiểm tra quan hệ giữa các construct.

Ví dụ:

PE, EE, SI, FC, DR, TR → BI → AU

Tại sao cần? (Why?)

Sau khi measurement model đạt chất lượng chấp nhận được, ta mới kiểm tra các giả thuyết về quan hệ giữa construct.

Khai báo structural model

structural_model <- '
  PE =~ pe1 + pe2 + pe3 + pe4
  EE =~ ee1 + ee2 + ee3 + ee4
  SI =~ si1 + si2 + si3 + si4
  FC =~ fc1 + fc2 + fc3 + fc4
  DR =~ dr1 + dr2 + dr3 + dr4
  TR =~ tr1 + tr2 + tr3 + tr4
  BI =~ bi1 + bi2 + bi3
  AU =~ au1 + au2 + au3

  BI ~ PE + EE + SI + FC + DR + TR
  AU ~ BI + FC
'

NoteKiến thức nền tảng (Knowledge Notes)

Bất biến đo lường là gì? (What is Measurement Invariance?)

Bất biến đo lường kiểm tra xem thang đo có cùng ý nghĩa giữa các nhóm hay không.

Ba mức cơ bản

Mức Ý nghĩa
Configural Cấu trúc nhân tố giống nhau
Metric Factor loadings giống nhau
Scalar Intercepts giống nhau

Tại sao cần? (Why?)

Nếu thang đo không tương đương giữa các nhóm, việc so sánh mean hoặc path coefficients có thể sai.

Ví dụ logic invariance

if ("gender" %in% names(sem_data)) {
  fit_configural <- cfa(
    measurement_model,
    data = sem_data,
    group = "gender",
    std.lv = TRUE
  )

  fit_metric <- cfa(
    measurement_model,
    data = sem_data,
    group = "gender",
    group.equal = "loadings",
    std.lv = TRUE
  )

  fit_scalar <- cfa(
    measurement_model,
    data = sem_data,
    group = "gender",
    group.equal = c("loadings", "intercepts"),
    std.lv = TRUE
  )

  invariance_table <- tibble(
    model = c("Configural", "Metric", "Scalar"),
    cfi = c(
      fitMeasures(fit_configural, "cfi"),
      fitMeasures(fit_metric, "cfi"),
      fitMeasures(fit_scalar, "cfi")
    ),
    rmsea = c(
      fitMeasures(fit_configural, "rmsea"),
      fitMeasures(fit_metric, "rmsea"),
      fitMeasures(fit_scalar, "rmsea")
    )
  )

  invariance_table
}

# 1. SEM nâng cao là gì?

::: {.callout-note title="Kiến thức nền tảng (Knowledge Notes)"}

**Là gì? (What?)**

Mô hình phương trình cấu trúc (Structural Equation Modeling - SEM) là phương pháp phân tích cho phép kiểm tra mối quan hệ giữa các biến tiềm ẩn (Latent Variables) và các biến quan sát (Observed Indicators).

**Tại sao cần? (Why?)**

SEM hữu ích khi nghiên cứu có:

- Nhiều construct lý thuyết
- Nhiều thang đo Likert
- Nhiều mối quan hệ đồng thời
- Mô hình trung gian hoặc điều tiết phức tạp
- Nhu cầu kiểm tra chất lượng thang đo

**Khi nào dùng? (When?)**

Dùng SEM khi câu hỏi nghiên cứu liên quan đến mô hình lý thuyết, thang đo và quan hệ giữa các construct.

**Thực hiện thế nào? (How?)**

SEM thường gồm hai phần:

1. Mô hình đo lường (Measurement Model)
2. Mô hình cấu trúc (Structural Model)

:::

::: {.callout-important title="Ứng dụng trong nghiên cứu (Research Application)"}

SEM thường được dùng trong:

- Nghiên cứu giáo dục
- Nghiên cứu hành vi người học
- Nghiên cứu chấp nhận công nghệ
- Nghiên cứu marketing
- Nghiên cứu quản trị
- Nghiên cứu tâm lý học
- Nghiên cứu sử dụng thang đo Likert

:::

::: {.callout-warning title="Sai lầm thường gặp (Common Mistakes)"}

Người học thường mắc lỗi:

- Chạy structural model khi chưa kiểm tra measurement model
- Chỉ báo cáo path coefficients mà bỏ qua model fit
- Dùng SEM khi không có cơ sở lý thuyết
- Không kiểm tra reliability và validity
- Diễn giải SEM cắt ngang như bằng chứng nhân quả mạnh

:::

# 3. PLS-SEM và CB-SEM

::: {.callout-tip title="Kết quả học tập (Learning Outcomes)"}

Sau phần này, học viên có thể:

- Phân biệt PLS-SEM và CB-SEM
- Biết khi nào dùng từng hướng tiếp cận
- Hiểu vì sao CFA thường gắn với CB-SEM

:::

::: {.callout-note title="Kiến thức nền tảng (Knowledge Notes)"}

**PLS-SEM là gì?**

PLS-SEM (Partial Least Squares SEM) thường được dùng khi mục tiêu là dự đoán, khám phá hoặc khi mô hình phức tạp với yêu cầu phân phối linh hoạt hơn.

**CB-SEM là gì?**

CB-SEM (Covariance-Based SEM) tập trung vào việc kiểm tra mô hình lý thuyết và độ phù hợp giữa ma trận hiệp phương sai quan sát và mô hình giả định.

**Khi nào dùng?**

| Mục tiêu | Gợi ý |
|---|---|
| Kiểm định lý thuyết mạnh | CB-SEM |
| Dự đoán construct phụ thuộc | PLS-SEM |
| Tập trung model fit | CB-SEM |
| Mô hình khám phá hoặc prediction | PLS-SEM |
| CFA nghiêm ngặt | CB-SEM |

:::

::: {.callout-warning title="Sai lầm thường gặp (Common Mistakes)"}

Không nên nói PLS-SEM luôn tốt hơn hoặc CB-SEM luôn tốt hơn.

Lựa chọn phụ thuộc vào:

- Câu hỏi nghiên cứu
- Mục tiêu phân tích
- Lý thuyết
- Dữ liệu
- Yêu cầu công bố

:::

# 4. Mô hình đo lường

::: {.callout-tip title="Kết quả học tập (Learning Outcomes)"}

- Hiểu biến tiềm ẩn (Latent Variable)

- Xác định item thuộc construct nào
- Viết mô hình đo lường bằng cú pháp `lavaan`

:::

::: {.callout-note title="Kiến thức nền tảng (Knowledge Notes)"}

**Biến tiềm ẩn là gì? (What is a Latent Variable?)**

Biến tiềm ẩn là construct không quan sát trực tiếp được, ví dụ:

- Performance Expectancy
- Effort Expectancy
- Social Influence
- Trust
- Behavioral Intention

**Biến quan sát là gì? (What is an Observed Indicator?)**

Biến quan sát là các câu hỏi hoặc item dùng để đo construct.

Ví dụ:

```text
PE =~ pe1 + pe2 + pe3 + pe4
```

nghĩa là construct `PE` được đo bằng 4 item.

:::

# 8. Giá trị hội tụ và giá trị phân biệt

::: {.callout-tip title="Kết quả học tập (Learning Outcomes)"}

Sau phần này, học viên có thể:

- Hiểu giá trị hội tụ (Convergent Validity)
- Hiểu giá trị phân biệt (Discriminant Validity)
- Tính AVE ở mức thực hành
- Hiểu logic Fornell-Larcker

:::

::: {.callout-note title="Kiến thức nền tảng (Knowledge Notes)"}

**Giá trị hội tụ là gì? (Convergent Validity)**

Các item đo cùng một construct nên hội tụ với nhau.

Chỉ số thường dùng:

```text
AVE > .50
```

**Giá trị phân biệt là gì? (Discriminant Validity)**

Các construct khác nhau nên đủ khác biệt với nhau.

Logic Fornell-Larcker:

```text
sqrt(AVE) của một construct nên lớn hơn tương quan của construct đó với construct khác.
```

:::

## Tính AVE đơn giản từ standardized loadings

::: {.callout-important title="Diễn giải kết quả (Interpretation)"}

Nếu AVE > .50, construct thường được xem là đạt giá trị hội tụ ở mức chấp nhận được.

Nếu AVE thấp, cần kiểm tra:

- Item loading thấp
- Nội dung item chưa nhất quán

**Mô hình cấu trúc là gì? (What is a Structural Model?)**

Mô hình cấu trúc kiểm tra quan hệ giữa các construct.


```{r}
structural_model <- '
```

# 12. Bất biến đo lường

:::

::: {.callout-note title="Kiến thức nền tảng (Knowledge Notes)"}

**Bất biến đo lường là gì? (What is Measurement Invariance?)**

Bất biến đo lường kiểm tra xem thang đo có cùng ý nghĩa giữa các nhóm hay không.

**Ba mức cơ bản**

| Mức | Ý nghĩa |
|---|---|
| Configural | Cấu trúc nhân tố giống nhau |
| Metric | Factor loadings giống nhau |
| Scalar | Intercepts giống nhau |

**Tại sao cần? (Why?)**

Nếu thang đo không tương đương giữa các nhóm, việc so sánh mean hoặc path coefficients có thể sai.

:::

## Ví dụ logic invariance

```{r}
if ("gender" %in% names(sem_data)) {
  fit_configural <- cfa(
    measurement_model,
    data = sem_data,
    group = "gender",
    std.lv = TRUE
  )

  fit_metric <- cfa(
    measurement_model,
    data = sem_data,
    group = "gender",
    group.equal = "loadings",
    std.lv = TRUE
  )

  fit_scalar <- cfa(
    measurement_model,
    data = sem_data,
    group = "gender",
    group.equal = c("loadings", "intercepts"),
    std.lv = TRUE
  )

  invariance_table <- tibble(
    model = c("Configural", "Metric", "Scalar"),
    cfi = c(
      fitMeasures(fit_configural, "cfi"),
      fitMeasures(fit_metric, "cfi"),
      fitMeasures(fit_scalar, "cfi")
    ),
    rmsea = c(
      fitMeasures(fit_configural, "rmsea"),
      fitMeasures(fit_metric, "rmsea"),
      fitMeasures(fit_scalar, "rmsea")
    )
  )

  invariance_table
}
```

::: {.callout-warning title="Sai lầm thường gặp (Common Mistakes)"}

Không nên so sánh nhóm trực tiếp nếu chưa kiểm tra measurement invariance.

:::

# 13. Viết kết quả học thuật

::: {.callout-note title="Kiến thức nền tảng (Knowledge Notes)"}

**Là gì? (What?)**

Viết kết quả SEM cần trình bày rõ:

- Measurement model
- Model fit
- Reliability
- Validity
- Structural paths
- R-squared
- Interpretation

:::

## Template CFA

```text
A confirmatory factor analysis was conducted to assess the measurement model. The model showed acceptable fit to the data, with CFI = [value], TLI = [value], RMSEA = [value], and SRMR = [value]. Standardized factor loadings were generally above [threshold], suggesting that the items adequately represented their intended constructs.
```

## Template reliability and validity

```text
Reliability analysis indicated that Cronbach's alpha values ranged from [min] to [max], exceeding the commonly recommended threshold of .70. Convergent validity was assessed using average variance extracted (AVE), with most constructs meeting the recommended threshold of .50.
```

## Template structural model

```text
The structural model was estimated to examine the hypothesized relationships among the latent constructs. The results showed that [predictor] significantly predicted [outcome], while [predictor] was not statistically significant. The model explained [R2]% of the variance in [outcome].
```

::: {.callout-warning title="Sai lầm thường gặp (Common Mistakes)"}

Không nên viết:

```text
SEM proved that X causes Y.
```

Nên viết:

```text
The SEM results suggest that X was positively associated with Y in the proposed model.
```
